# D/E模型推荐评分机制

> 用途：新题进入 Skill 后，不直接指定算法，而是先对候选模型进行结构化评分。

## 1. 推荐原则

模型推荐不是“哪个模型高级选哪个”，而是评价：

> 题意匹配度 + 数据适配度 + 约束适配度 + 可解释性 + 可验证性 + 稳健性 + 计算成本

## 2. 六维评分

每个候选模型按 0—5 分评分：

| 维度 | 含义 |
|---|---|
| 题意匹配 | 是否直接解决题目要求 |
| 数据适配 | 当前附件是否支持该模型 |
| 约束适配 | 能否自然表达题目约束 |
| 可解释性 | 能否解释变量和结果 |
| 可验证性 | 是否容易进行独立检验 |
| 稳健性 | 参数变化后结果是否稳定 |
| 计算成本 | 数据规模下是否可接受 |

## 3. 推荐分数

默认综合分：

`Score = 0.25S题意 + 0.15S数据 + 0.15S约束 + 0.15S解释 + 0.15S验证 + 0.10S稳健 + 0.05S计算`

权重不是固定真理。若题目明确强调预测精度，可以提高数据适配与泛化相关权重；若是工程优化，则提高约束适配和稳健性权重。

## 4. D题推荐规则

D题通常优先：

1. 机理模型
2. 概率/统计模型
3. 优化模型
4. 网络/路径模型
5. 仿真模型
6. 数据驱动融合模型

如果两个模型分数接近，优先选择更容易解释、验证和写入论文的模型。

## 5. E题推荐规则

E题通常优先：

1. 数据分析/统计基线
2. 回归/时间序列
3. 分类/聚类
4. 树模型/集成模型
5. 机器学习/深度学习
6. 预测结果驱动的优化模型

复杂模型必须证明相对于基线模型的实际收益。

## 6. 硬性淘汰条件

即使综合分较高，存在以下情况也应淘汰：

- 数据量明显不足
- 关键变量无法获得
- 明显违反题目约束
- 需要未来信息导致数据泄漏
- 结果不可解释且题目要求解释
- 训练/仿真过程无法复现
- 只能得到漂亮指标，无法回答题目问题

## 7. 输出格式

处理新题时要求输出：

| 候选模型 | 题意 | 数据 | 约束 | 解释 | 验证 | 稳健 | 成本 | 综合分 | 结论 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 模型A |  |  |  |  |  |  |  |  |  |
| 模型B |  |  |  |  |  |  |  |  |  |
| 模型C |  |  |  |  |  |  |  |  |  |

最后必须写明：

> 主模型为什么选它；备选模型为什么没有采用；如果数据或约束改变，模型选择是否需要重新判断。
