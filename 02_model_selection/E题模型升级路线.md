# E题模型升级路线

## 1. 总体流程

> 数据审计 → EDA → 数据清洗 → 特征/指标 → 基线模型 → 候选模型 → 交叉验证/时间验证 → 模型比较 → 解释 → 预测/评价 → 决策优化

E题最重要的不是“算法多”，而是数据链条完整。

## 2. 数据审计清单

### 2.1 数据结构

- 样本量、变量数
- 数值/类别/文本/时间变量
- 时间粒度和空间粒度
- 主键是否唯一
- 是否存在重复记录

### 2.2 数据质量

- 缺失值比例与缺失机制
- 异常值与极端值
- 单位不一致
- 时间错位
- 逻辑冲突
- 数据截断

### 2.3 防止数据泄漏

任何会使用未来信息或测试集信息的处理，都必须避免。例如：

- 标准化参数只能由训练集计算。
- 插补规则不能用测试集统计量。
- 特征选择不能先看完整测试集标签。
- 时间序列不能随机打乱后普通交叉验证。

## 3. 基线模型

根据任务优先建立可解释基线：

| 任务 | 基线 |
|---|---|
| 连续值预测 | 均值/持久性、线性回归、岭回归 |
| 二分类 | Logistic、决策树 |
| 多分类 | Logistic/树模型 |
| 时间序列 | Naive、移动平均、指数平滑、ARIMA |
| 聚类 | K-means、层次聚类 |
| 综合评价 | 标准化 + 简单加权 |

基线的作用是回答：复杂模型到底有没有真正增加价值？

## 4. 模型升级

### 4.1 回归

线性回归 → Ridge/Lasso → 随机森林/梯度提升 → XGBoost/LightGBM → 非线性集成。

升级依据：非线性、交互作用、维度、样本量和泛化误差。

### 4.2 时间序列

Naive → 移动平均/指数平滑 → ARIMA/SARIMA → 特征回归/树模型 → 深度学习。

深度学习不是默认选择。样本短、解释要求高时，经典模型往往更合适。

### 4.3 分类

Logistic → 决策树 → 随机森林/梯度提升 → SVM/其他模型。

关注：类别不平衡、阈值选择、混淆矩阵、Precision/Recall/F1/AUC。

### 4.4 聚类

K-means → 层次聚类 → DBSCAN/GMM。

不能只给聚类结果，应说明特征标准化、簇数依据和业务解释。

## 5. E题的“模型比较表”必须回答

- 精度谁更好？
- 稳定性谁更好？
- 解释性谁更好？
- 计算成本是否可接受？
- 是否符合题目机理？
- 是否能外推到题目要求的预测区间？

最终选择不一定是指标最高的模型，而应是“精度、稳定性、解释性、可实施性”的综合最优。
