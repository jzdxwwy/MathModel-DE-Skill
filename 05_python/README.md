# 05 Python：可复现求解层

本目录不是算法堆砌，而是把“模型 → 代码 → 结果”固定成可追溯链条。

## 标准顺序

1. 读取原始附件，不修改原始文件。
2. 记录数据审计结果。
3. 建立 `problem_config`：变量、单位、参数、约束、随机种子。
4. 先写最小可运行 baseline。
5. 实现主模型。
6. 保存中间结果和最终结果。
7. 生成图表所需的结构化数据。
8. 运行独立验证。
9. 冻结关键数字后才交给论文层。

## 硬规则

- 禁止把手算或猜测数字写进最终结果文件。
- 随机算法必须固定 seed，并记录 seed。
- 时间序列禁止随机打乱训练/测试集。
- 同一对象多条记录时，优先使用 GroupKFold / Group split。
- 优化问题必须检查约束可行性。
- 仿真必须报告重复次数、随机种子、关键统计量及稳定性。
- 每一个论文数字都必须能追溯到 `results/` 或真实生成的图表数据。
- 如果代码未实际运行，必须明确标记“待运行”，不得声称得到数值结果。
