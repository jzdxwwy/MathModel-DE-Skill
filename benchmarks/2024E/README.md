### 0.2 子问题（依据题目原文提炼）

1. **时段划分与流量估计**：对经中路-纬中路交叉口，按车流量差异把一天分成若干时段，
   估计不同时段各相位（含四方向直行、转弯）的车流量。
2. **信号灯优化配置**：对两条主路上所有交叉口的信号灯优化配置，在保证通行的前提下
   使两条主路车流平均速度最大。
3. **巡游车辆识别与停车位估算**：分析五一黄金周数据，判定寻找停车位的巡游车辆，
   估算假期景区需临时征用多少停车位。
4. **管控措施效果评价**：五一期间实行了临时交通管理措施（见附件 3），
   结合数据评价其在两条主路上的效果。

### 0.5 本轮在该文件上实测到的两个真问题

**（1）编码：附件 2 是 GB18030，不是 UTF-8**

这是本轮最严重的发现，且**由这道题才暴露出来**：

| 层 | 修复前行为 |
| --- | --- |
| ingestion（`_csv_profile`，`errors="replace"`） | 产出**乱码列名** `['����','ʱ��',…]`，**且不报任何警告** |
| 计算层（模板 `pd.read_csv` 默认 UTF-8） | **直接 UnicodeDecodeError 崩溃** |

即同一个文件，一端静默损坏、一端硬失败。已修复：显式探测编码（先 utf-8 严格试，
再 gb18030），把探测结果记入 profile；探测用**增量解码器**，避免 256 KB 采样
正好把汉字切成两半（实测该文件的失败位置正是 262143——采样窗口的最后一个字节）。
计算层则在 adapter 里一次性流式转码为 UTF-8。

修复后实测：

```
detect_text_encoding  -> gb18030, lossless=True
_fast transcode        -> 6.3 s  (520 MB UTF-8)
transcoded header      -> "方向","时间","车牌号","交叉口"
ingest columns         -> ['方向','时间','车牌号','交叉口']   （不再是乱码）
ingest rows            -> 8,844,996
```

**（2）规模与内存**

| 环节 | 实测 |
| --- | --- |
| ingestion（流式逐行计数） | 884 万行 / **9–11 秒** / **峰值 26 MB** —— 有界，没有把文件读进内存 |
| adapter 转码（文本级拷贝） | 6.3 秒，内存有界 |
| **模板层** | 仍是 `pd.read_csv` **全量读取、无分块** —— 这是尚未解决的缺口 |

也就是说：**数据进得来、转得动，但现有模板算不动**。`data_audit.py` 里有
`DEFAULT_CHUNK_SIZE`，说明仓库意识到了分块需求，但那条路径没有被任何模型族使用。

## 1. Benchmark定位

这是一个典型的“交通数据分析 + 流量规律识别 + 管控方案评价/优化”E题案例。

2024年全国大学生数学建模竞赛官方资料将E题确定为“交通流量管控”，并在赛题讲评中对背景、解决思路、具体模型和求解方法进行了专题解析。citeturn0search0turn0search4

## 2. 题型标签

`交通流` `时间序列` `统计分析` `预测` `管控评价` `优化` `仿真` `时空数据`

## 3. 建模主线

建议采用：

> 数据体检 → 时空特征分析 → 流量规律建模 → 交通状态/需求预测 → 管控措施评价 → 方案优化 → 情景仿真 → 稳健性分析

## 4. 数据分析优先级

### 第一层：数据审计

检查：

- 时间字段和采样间隔
- 交通流量单位
- 缺失记录
- 重复记录
- 异常峰值
- 节假日/工作日
- 高峰/平峰
- 不同路段或入口的对应关系

### 第二层：探索性分析

建议绘制：

- 日内流量曲线
- 工作日/周末对比
- 热力图
- 路段相关性矩阵
- 峰值时段统计
- 累计流量

## 5. 候选模型

### 时间序列基线

先使用：

- Naive
- 移动平均
- 指数平滑
- ARIMA/SARIMA

用于判断复杂模型是否真的带来增益。

### 回归模型

如果流量受时间、天气、节假日、路段等变量影响，可使用多元回归、岭回归或树模型。

### 聚类

如果需要识别交通状态或不同时间段/路段模式，可使用K-means、层次聚类等。

### 管控优化

如果最终需要确定信号配时、限流比例、入口控制或资源分配，应把交通分析结果转化为优化模型：

- 决策变量
- 目标函数
- 约束条件
- 可行域
- 求解算法

## 6. 仿真使用规则

仿真应服务于决策，而不是为了“画出一条漂亮曲线”。

至少设置：

- 基准情景
- 管控情景
- 极端/压力情景

比较平均速度、拥堵程度、通行量、排队长度等指标。

## 7. E题特别注意

### 不要随机打乱所有时间数据

如果目标是预测未来，应使用时间顺序划分训练集/验证集/测试集。

### 不要只追求预测精度

如果题目最终要求交通管控方案，预测只是中间环节，必须继续回答“预测结果如何转化为管控决策”。

### 不要机械堆叠模型

可以比较2—4个有代表性的模型，但必须说明：

- 为什么选它们
- 指标差异
- 稳定性
- 解释性
- 最终为什么采用某一个

## 8. 验证体系

推荐至少包含：

- MAE
- RMSE
- MAPE（数据允许时）
- R²（回归任务适用时）
- 残差分析
- 时间外推验证
- 情景敏感性
- 管控方案稳健性
