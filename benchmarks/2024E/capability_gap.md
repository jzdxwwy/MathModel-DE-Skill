# 2024E Benchmark：能力缺口清单

> 本文件不是 2024E 的解题答案，而是用该历史题检验 `MathModel-DE-Skill` 的能力覆盖度。

## 1. 已暴露的能力

| 能力 | 2024E 暴露方式 | Skill化要求 |
|---|---|---|
| 大规模数据处理 | 百万级车辆事件记录 | 分块读取、体检、哈希、阶段性落盘 |
| 事件流重构 | 车辆ID + 时间 + 交叉口 | 实体内排序、相邻事件、时间间隔诊断 |
| 网络结构 | 道路/交叉口/距离 | 节点边抽象、网络约束接口 |
| 隐变量处理 | 左/直/右转不可直接观测 | 观测层与推断层分离 |
| 时段发现 | 根据车流差异划分时段 | 聚合 + 变点/聚类 + 粒度敏感性 |
| 约束优化 | 信号配时 | 目标、硬约束、可行性检查、优化器比较 |
| 轨迹特征 | 黄金周停车巡游识别 | 停留、重复访问、绕行等通用特征接口 |
| 干预评价 | 临时交通管控 | 前后对比、匹配、敏感性/稳健性 |

## 3. 下一阶段优先级

### P0：事件流数据审计

必须能回答：

- 数据规模是多少？
- 时间覆盖范围是什么？
- 实体数量是多少？
- 每个实体记录数分布如何？
- 时间戳是否可解析？
- 重复事件比例是多少？
- 单实体是否存在倒序时间？
- 节点/状态类别是否稳定？

### P0：轨迹重构

必须输出：

- 有序事件表
- 相邻转移表
- 时间间隔
- 大间隔标记
- 同节点重复标记
- 推断状态与观测事实分离

### P1：网络约束接口

把“节点是否相邻”“候选路径”“距离/时间成本”等问题独立出来，供不同 D/E 题复用。

### P1：时空聚合与时段发现

建立从事件流到：

\[
Q_{location,category,time-window}
\]

的通用聚合接口，并支持多个窗口粒度的敏感性检查。

### P2：隐变量/事件推断

建立通用接口，而不是直接绑定“左直右转”：

```text
observed events
    ↓
constraints / candidate states
    ↓
rule baseline
    ↓
probabilistic or ML upgrade
    ↓
uncertainty / confidence
```

### P2：干预评价

建立通用的 intervention evaluation 模块，支持：

- before/after
- matched comparison
- bootstrap/permutation
- DID（仅在设计与假设合理时）

## 4. Benchmark 验收原则

历史题 Benchmark 通过的条件不是“得到标准答案”，而是：

1. 能识别题型与数据结构；
2. 能发现相应能力缺口；
3. 能调用通用模板完成结构化处理；
4. 能通过 synthetic smoke test；
5. 能用真实历史附件做回归验证；
6. 输出可追溯、可验证且不依赖题目专属硬编码。

## 5. 不允许的做法

- 不把 2024E 的字段名写死进通用模块；
- 不把历史题答案作为 Skill 的固定规则；
- 不以一次题目的高分结果证明 Skill 泛化；
- 不用未知数据补齐 benchmark 结果；
- 不因数据量大就默认使用深度学习；
- 不因存在网络就默认使用最复杂图模型。
