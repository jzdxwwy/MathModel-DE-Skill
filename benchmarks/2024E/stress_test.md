# 2024E 压力测试：交通流量管控

> 用途：作为 E 类数据分析 + 时段识别 + 交通优化 + 异常/巡游车辆识别 + 政策效果评价的历史回归测试。

## 1. 题型标签

- E 类：多源时空车辆数据分析
- 数据对象：车牌、时间、监控点、行驶方向、路段距离等
- 核心任务：时段划分、转向流量估计、信号灯优化、巡游车辆识别、停车需求估算、政策效果评价
- 主要风险：时间泄漏、车辆重复计数、路段出入口导致的“突然出现/消失”、假日与平日分布漂移、管控措施与日期强相关造成混杂

## 2. 子问题拆解

### 问题1：时段划分与车流量估计

题目要求在经中路—纬中路交叉口，根据车流量差异划分一天时段，并估计不同时间段四个方向、直行和转弯车流量。

Skill 应执行：
1. 数据体检：时间字段、车牌字段、监控点、方向编码、重复记录；
2. 按天/时段聚合车流量，避免把跨天数据直接混合；
3. 用 K-means、层次聚类或变点方法形成候选时段；
4. 用轮廓系数、组内方差、业务可解释性比较时段数；
5. 对监控无法直接观察的转向流量，明确说明识别假设与估计方法，不能把未知量当作观测量。

### 问题2：信号灯优化

目标是在保证车辆通行约束下，使两条主路车流平均速度最大。

Skill 应输出：
1. 路网/交叉口抽象；
2. 各相位需求、周期、绿灯时长、黄灯/全红时间等决策变量；
3. 通行能力、排队/延误或速度目标函数；
4. 约束：周期上下界、最小绿灯、相位总时长、协调偏移等；
5. 基线方案与优化方案对比；
6. 可行性检查和扰动敏感性。

首选路线：

`流量估计 → 容量/延误基线 → 非线性/混合优化 → 方案仿真或离散时间验证`

不要直接把“机器学习预测精度”当作信号灯优化目标。

### 问题3：巡游车辆与停车位需求

目标是识别五一期间寻找停车位的巡游车辆，并估算景区临时停车位需求。

建议特征：

- 单车在景区周边的持续时间
- 行驶距离
- 平均速度/低速占比
- 重复经过同一监控点或路段次数
- 轨迹回访/近似闭环特征
- 时段与景区高峰的关系

识别模型可以从规则基线开始，再比较聚类/分类模型。若没有人工标签，不得声称“监督分类准确率”。

停车需求应与“车辆到达率 + 停留时间 + 停车容量”联系起来，可使用占用率、峰值需求、排队/库存思想或离散事件模拟。

### 问题4：临时交通管控效果评价

必须明确比较口径：

- 管控前 vs 管控后
- 同一时段 vs 同一时段
- 同一路段/交叉口
- 平日基线 vs 假日基线

推荐指标：平均速度、旅行时间、流量、排队/拥堵代理指标、巡游车辆比例、路网吞吐量。

优先使用差异化比较、分时段对照、Bootstrap/置换检验等；如果数据结构允许，可进一步考虑 Difference-in-Differences 思路，但必须检查平行趋势等条件。

## 3. E 题数据门禁

运行任何模型前必须完成：

- [ ] 时间字段合法
- [ ] 车牌/车辆 ID 是否存在缺失
- [ ] 监控点编码统一
- [ ] 方向编码统一
- [ ] 重复记录处理
- [ ] 同车跨监控点时间顺序合理
- [ ] 异常速度/负时间差检查
- [ ] 假日与平日分布差异检查
- [ ] 训练/验证划分避免同一车辆跨集合造成泄漏

## 4. 推荐模板组合

- `time_series_cv.py`：时序验证
- `classification_cv.py`：有标签时的巡游车辆分类
- `model_compare.py`：候选预测/分类模型比较
- `optimization.py`：信号配时优化原型
- `sensitivity.py`：参数敏感性

若使用历史车辆数据做机器学习，默认优先按“车辆/日期/时间块”分组切分，而不是随机打散全部记录。

## 5. 回归检查项

- [ ] 聚类得到的时段有业务解释
- [ ] 转弯流量的不可观测性被明确处理
- [ ] 优化方案满足全部信号约束
- [ ] 巡游车辆判定有可复核规则/特征
- [ ] 停车位需求不是简单把“巡游车辆数量”当成“车位数量”
- [ ] 政策效果评价控制了时段、日期和流量基线差异
- [ ] 图表全部由实际数据运行生成
- [ ] 没有把参考论文结果硬编码为自己的结果
